## Four Product Decisions

### AI failure never costs the educator a credit

In pedagogical routes, a failure after debit triggers a credit refund. In planning, model fallback is conditional and depends on configuration. The policy varies by generator.

### AI cost became pricing

Credits are the consumption unit, with cost per generation type. The commercial model offers period-based plans and one-off packs. Trade-off: pricing and model costs must evolve together.

### Predictability over fluidity

Synchronous generation prioritizes predictability when progressive responses do not preserve material integrity. Trade-off: less sense of immediate response.

<h2 id="falha-de-ia">AI Fails. The Policy Must Be Explicit.</h2>

A provider failure should not leave the educator without material or charge for a generation that did not complete. In pedagogical routes, a failure after a new debit triggers a credit refund.

The policy is not universal. Planning has a conditional OpenAI fallback when the failure is recoverable and the second provider is configured. Other flows follow their own rules.

ProfResolve uses **credits** as its consumption unit. Each generation type has a different cost, and the price of a generation is a product decision, not just an infrastructure variable.

Credits sit at the intersection of computational cost, perceived value and monetization. When a model's cost changes, it directly affects the price of a generation and how users are likely to behave.

Each generator's cost needs to reflect its strategy and model so AI consumption stays visible and manageable within the product.

### Stack and Architecture Decisions

ProfResolve was built with Next.js App Router as the unified base for frontend, API routes and business logic. The choice eliminated the need for a separate server and allows generation, authentication and credit logic to live in the same process, with API routes organized by domain.

#### PostgreSQL for permanent state. Redis for temporary state.

PostgreSQL stores everything that requires consistency: users, credits, materials, payments, generation history. Access is via raw SQL through `pg` — no ORM — making every query explicit and auditable.

Redis (Upstash) solves three performance and resilience problems: session cache with a 30-second TTL to avoid hitting the database on every authenticated request; fixed-window rate limiting via `INCR/EXPIRE` in pipeline to protect generation endpoints; and credit balance invalidation after every debit or refund.

The Redis client has a fallback layer: if Upstash is unavailable, the application automatically falls back to an in-memory provider with reduced limits without interrupting the service. The trade-off is accepting less precise rate limits in degraded mode rather than blocking requests.

#### Cloudflare R2 for temporary generator attachments.

Educators can upload PDFs as context for some generators. The flow uses a server-generated pre-signed URL: the browser uploads directly to R2 without going through the application server, reducing latency and bandwidth.

R2 is accessed via an S3-compatible SDK (`@aws-sdk/client-s3`) pointed at the Cloudflare endpoint. This allows using the same AWS ecosystem abstractions without depending on AWS infrastructure. The bucket is temporary — files are read during generation and deleted afterwards. The feature has an independent activation flag.

PDF export follows a different path: the server renders the material HTML with Playwright (headless Chromium) and returns the bytes directly — R2 is not involved in that flow.

#### Better Auth with database provisioning hooks.

Authentication uses Google OAuth only — no local password. The choice reduces the attack surface and eliminates password recovery flows. Session management uses HTTP-only cookies; a custom Redis cache replaces Better Auth's native mechanism to allow explicit control over TTL and invalidation.

Better Auth's database hooks handle automatic provisioning: on user creation, the system assigns the freemium plan, inserts the initial credit record and registers the provider. This ensures every authenticated user has credits available from their first access, with no separate setup step.

Role-based access control (`freemium`, `pro`, `admin`) is implemented manually in `rbac.ts` — no Better Auth RBAC plugins are in use. Middleware protects `/dashboard/*` and `/admin/*` via cookie verification, with full session validation as an optional second layer, controlled by feature flag.

#### Vitest for API contracts. Playwright for critical product flows.

Vitest tests cover two environments: `node` for API routes, services and server utilities; and `dom` (happy-dom) for React hooks, client logic and stateful components. Property-based tests with `fast-check` validate payload validation endpoints against generated inputs — empty arrays, invalid IDs, wrong types — ensuring input boundaries are robust.

Playwright tests cover the flows a real user goes through: authentication with redirect, generator modal, credit display, editor, materials and critical error scenarios. They follow the Page Object Model pattern. The Asaas checkout is explicitly excluded from e2e tests due to its dependency on an external service.

The separation is intentional: Vitest validates contracts and business logic quickly in isolation; Playwright validates observable educator behavior with higher execution cost but end-to-end coverage.

### Engineering as Part of Product Trust

Test coverage and engineering discipline are not just technical concerns on ProfResolve. They are part of the strategy to keep the platform reliable as new features are developed.

The combination of automated tests, strict TypeScript, sanitized logs, a health endpoint, Analytics and Clarity supports failure investigation and reduces risk during product evolution.

For critical operations like credits and payments, idempotency prevents duplicate processing during repeated attempts at the same operation. These are engineering decisions that protect the educator's experience and contribute to business reliability.
